# Oak Report

This repository now contains a first vertical slice of the Pokemon appraisal app:

- A FastAPI backend with SQLModel-backed Postgres persistence for auth and collection data
- A React/Vite frontend for uploading a card image and viewing appraisal results
- Product context docs under `docs/context/`

## Local backend with uv

1. Install `uv` if you do not already have it.
2. Copy `.env.example` to `.env` and adjust values if needed.
3. Create the environment with `uv sync`.
4. Start local Postgres (or use Docker Compose): `docker compose up -d postgres`.
5. Create and migrate the database: `./scripts/create_database.sh`.
6. Start FastAPI with `uv run uvicorn backend.main:app --host 0.0.0.0 --port 8000 --reload`.

The API will be available at `http://localhost:8000` and Swagger at `http://localhost:8000/docs`.

To reset the database during development/testing:

```bash
./scripts/reset_database.sh
```

`reset_database` clears schema state, re-runs Alembic migrations, and reseeds baseline data from `data/pokemon_cards.csv`.

## Alembic (database migrations)

Alembic is the schema migration system for the backend Postgres database. In this project, it keeps table/index changes versioned and reproducible across local development, dev containers, and Docker.

What it manages right now:

- Versioned migration files under `alembic/versions/`
- Migration configuration in `alembic.ini` and `alembic/env.py`
- Schema updates for auth and collection tables (for example, the initial migration creates `users` and `collection_items`)

### Quick dev workflow

1. Make model changes in backend SQLModel models.
2. Create a new migration revision.
3. Apply migrations to your local database.
4. Run/reset seed scripts as needed for clean test data.

Common commands from repo root:

```bash
# Apply all pending migrations
uv run alembic upgrade head

# Create a new migration from model metadata changes
uv run alembic revision --autogenerate -m "describe_change"

# Roll back one migration
uv run alembic downgrade -1

# Show current migration state
uv run alembic current

# Show migration history
uv run alembic history
```

Project helper scripts:

```bash
# Create database (if missing), run migrations, then seed data
./scripts/create_database.sh

# Drop and recreate schema, then re-run migrations and reseed
./scripts/reset_database.sh
```

Notes:

- Commit migration files together with model changes.
- Review autogenerated migrations before committing.
- Keep migration files forward-only for shared environments; use new revisions instead of editing applied ones.

## Frontend

1. Copy `.env.example` values into your local environment if needed.
2. From `frontend/`, install dependencies with `npm install`.
3. Start the frontend with `npm run dev`.

The Vite app runs at `https://localhost:5173` and is already allowed by backend CORS.

## Containers

Start the full stack with:

```bash
docker compose up --build
```

This launches:

- Postgres on `localhost:5432`
- FastAPI backend on `http://localhost:8000`
- React/Vite frontend on `https://localhost:5173`

The backend image uses `uv` and `pyproject.toml` for Python dependency management.

## Current scope

Auth and collection APIs now persist to Postgres when `DATA_PROVIDER=postgres`.

The scan and library/search flows are still intentionally mocked. Scan returns:

- normalized card identity
- condition snapshot
- estimated market value
- sample pricing sources

This keeps a stable contract while preserving staged migration for remaining domains.

## Data provider boundaries

Repository adapters support provider selection so persistence can evolve without changing routes/screens.

- Backend provider switch:
  - `DATA_PROVIDER=mock`
  - `DATA_PROVIDER=postgres` (implemented for auth + collection)
- Backend repository boundaries:
  - `backend/repositories/collection_repository.py`
  - `backend/repositories/search_repository.py`
  - `backend/repositories/scan_catalog_repository.py`
  - `backend/repositories/factory.py`
- Frontend provider switch:
  - `VITE_DATA_PROVIDER=mock` (default)
  - `VITE_DATA_PROVIDER=api` (calls backend endpoints)
- Frontend repository boundaries:
  - `frontend/src/repositories/collectionRepository.ts`
  - `frontend/src/repositories/libraryRepository.ts`

Database migration tooling:

- Alembic config: `alembic.ini` and `alembic/`
- Create DB + migrate + seed: `./scripts/create_database.sh`
- Reset DB + migrate + reseed: `./scripts/reset_database.sh`
