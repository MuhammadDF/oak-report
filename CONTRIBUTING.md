# Contributing

Thanks for improving Oak Report. This guide keeps contributions predictable across backend, frontend, database, docs, and scripts.

## Workflow

1. Read the nearest `AGENTS.md` for the area you are changing.
2. Keep changes scoped to the requested behavior.
3. Update docs when commands, environment variables, architecture, or workflows change.
4. Run the narrowest useful tests first, then the full QA command when behavior changes.

## Setup

```bash
cp .env.example .env
uv sync
npm --prefix frontend install
docker compose up -d postgres
./scripts/create_database.sh
```

## Quality Commands

Full QA:

```bash
./scripts/run_qa.sh
```

Backend:

```bash
uv run pytest backend/tests
```

Frontend:

```bash
npm --prefix frontend run test
npm --prefix frontend run test:coverage
```

Build frontend:

```bash
npm --prefix frontend run build
```

## Standards

- Keep route handlers thin; put business behavior in services and data access in repositories.
- Preserve provider boundaries rather than importing concrete adapters into screens or routes.
- Keep React components focused and move reusable stateful behavior into hooks.
- Do not commit secrets, local `.env` values, coverage output, build artifacts, or generated caches.
- Commit Alembic migrations with schema/model changes.
- Review autogenerated migrations before committing.

## Documentation

The root README is a hub. Detailed procedures belong in `docs/`. If a change affects setup, operations, architecture, testing, or contribution workflow, update the matching doc.

## Pull Request Checklist

- Commands and environment documentation still match the repo.
- New or changed behavior has focused tests.
- Database changes include reviewed migrations.
- README links and docs links resolve.
- CI/CD claims remain honest: no badge or workflow should be referenced unless it exists.
