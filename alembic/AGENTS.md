# Alembic Agent Guide

Use this guide when changing `alembic`.

## Commands

```bash
uv run alembic upgrade head
uv run alembic revision --autogenerate -m "describe_change"
uv run alembic downgrade -1
uv run alembic current
uv run alembic history
```

## Standards

- Commit migrations with the model or schema changes that require them.
- Review autogenerated migrations before committing.
- Use descriptive revision messages.
- Keep shared migrations forward-only; add a new revision instead of editing an applied migration.
- Make downgrade behavior reasonable for local development when practical.

## Constraints

- Alembic reads `DATABASE_URL` first, then falls back to `POSTGRES_*`.
- Do not add data-destructive migration behavior without explicit task scope and tests.
- Keep `alembic/env.py` aligned with SQLModel metadata in `backend/db/models.py`.
