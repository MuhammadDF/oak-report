# Database Guide

Oak Report uses Postgres with SQLModel table definitions and Alembic migrations.

## Current Tables

Table definitions live in `backend/db/models.py`.

- `users`: Google-authenticated user records, roles, feature flags, account state, and timestamps.
- `collection_items`: user-owned card records with card identity, price, image, grade, and quantity.
- `pricing_catalog`: PriceCharting catalog rows with product identity, loose price, image URL, and refresh timestamp.

## Configuration

Database settings live in `backend/db/config.py`.

The backend uses `DATABASE_URL` when set. If it is empty, it builds an async Postgres URL from:

- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_HOST`
- `POSTGRES_PORT`
- `POSTGRES_DB`

Docker Compose maps `APP_DATABASE_URL` into backend `DATABASE_URL` and maps `DB_*` values into `POSTGRES_*` values.

## Migrations

Alembic config lives in `alembic.ini` and `alembic/`.

Apply migrations:

```bash
uv run alembic upgrade head
```

Create an autogenerated revision after model changes:

```bash
uv run alembic revision --autogenerate -m "describe_change"
```

Roll back one revision locally:

```bash
uv run alembic downgrade -1
```

Inspect state:

```bash
uv run alembic current
uv run alembic history
```

Review autogenerated migrations before committing. Commit migration files together with schema/model changes.

## Seed and Reset

Create, migrate, and seed:

```bash
./scripts/create_database.sh
```

Reset schema, migrate, and reseed:

```bash
./scripts/reset_database.sh
```

Seed data comes from `data/pokemon_cards.csv`.

## Testing

Backend tests create/use a test database derived from `DATABASE_URL` by appending `_test` to the database name. Keep tests isolated from local development data.
